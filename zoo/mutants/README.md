# The bug zoo

Each mutant is `zoo/cfr.py` (clean CFR+) with exactly one edit, generated by
`zoo/make_mutants.py` (which fails if an edit does not match the clean source exactly once).
`diff zoo/cfr.py zoo/mutants/<name>.py` shows the whole bug. Do not edit these files by hand.

Every solver carries the same three internal meters and its own stopping rule trusts them:
`self_exploitability` (a best response computed in the solver's OWN model of the game, the analog
of Red/Black's `eps_round`; tolerance 1e-3), `regret_meter` (average positive regret, 5e-2) and
`value_delta` (change of the average profile's value over 250 iterations, 1e-4). "Says converged"
means all three are under tolerance. True exploitability comes from `reference/br.py` (exact
fractions), cross-checked by `zoo/exact_br.py`; the two agreed exactly on all 144 rows, and
`zoo/showcase.py` regrades every row with the verified checker `bin/bluff`, which agrees exactly too.
A fourth meter, `color_swap_gap`, is reported but not part of the stopping rule (see
`color_swap_imposed`).

Reproduce: `uv run zoo/make_mutants.py && uv run zoo/run_zoo.py && uv run zoo/showcase.py`
(7.4 minutes with 6 jobs on a loaded 18-core Mac, then 8 s), results in `zoo/out/summary.json`
(144 rows: 9 games x 16 solver rows) and `zoo/out/showcase.json`. Rows tagged `@cfr` run the same
mutant under vanilla CFR.

Games: Kuhn, Leduc as the poker task wrote it (suited, every chance node uniform), `leduc_ranks`
(the same Leduc with suits merged, so the deals are not uniform), `dice_bluff_2round` (non-uniform
chance at two depths), and five Red/Black files from `games/out/redblack`: the dealt games `rb-h1`,
`rb-21`, `rb-12` (26/26 deck, non-uniform deal, a true color-swap automorphism) and the gate
endgame `rb-pennies` with its second stage `rb-pennies-inner` (a fixed position with no chance node,
where seat 0's known red breaks the color symmetry). `rb-pennies-leaky` is left out on purpose: it
is the deliberately wrong spec of the game-file trap, not a solver test.

## What the table says

- **Fooled rows are wrong models or wrong artifacts, never wrong updates.** All 19 fooled rows
  are `info_leak_key`, `chance_ignored` or `color_swap_imposed` (the solver solves a different game
  than the file: split infosets, wrong chance, merged infosets) or `current_not_average` (it ships a
  different strategy than the one its meters measured). In every case the meter is internally
  exact: it measures the game the solver thinks it is solving, or the strategy it did not ship.
  This is Paper II's failure ("converged by every internal meter while carrying values wrong by up
  to 0.11") in miniature: a meter that shares the solver's assumptions cannot see them.
- **Which game you test on decides what you see.** `chance_ignored` is exactly harmless on Kuhn and
  suited Leduc (every chance node uniform) and on the gate endgames (no chance node), nearly
  harmless on rb-h1 (0.0028: the 1-card deal is 25/102 vs 26/102, close to uniform), and costs
  0.10 to 0.36 on leduc_ranks, dice and the 2-card Red/Black deals. `reach_per_node` is invisible on
  Kuhn, rb-h1 and rb-pennies-inner (its meter says converged at the clean solver's number) and
  caught everywhere else;
  `info_leak_key` is harmless on the gate endgames, which have no chance node to leak. Averaging
  bugs show only under vanilla CFR.
- **`color_swap_imposed`: the right symmetry is free, the wrong one is invisible to its own
  meters.** On the dealt games the imposed swap is the true automorphism (every infoset's image is
  in the game with the swapped actions: `test_color_swap_is_an_automorphism_of_a_dealt_game`), and
  the mutant matches clean CFR+ (rb-21 1.5e-5 vs 1.2e-5, rb-12 1.3e-4 vs 2.8e-4). On rb-pennies,
  where seat 0 holds a known red, it ties 152 seat-1 infosets (76 pairs) to images that are not equivalent.
  All three meters say converged (self-BR 8.96e-4, regret 0.038, value delta 1.2e-6), the value is
  right (-0.499996 against the exact -1/2, the research's 25%), and `bin/bluff` certifies 0.0613,
  80 times clean CFR+ on the same file (7.6e-4). Its self-BR meter is blind for a structural
  reason: the best response is computed over the solver's merged rows, so the best responder is
  held to the same symmetry. The mutant's `color_swap_gap` reads exactly 0 on every dealt game,
  because shared rows cannot differ (the "reads zero because it was forced to" of
  `solve-2-kernel.md`).
- **The symmetry gap is not an error meter either.** Clean CFR+ on rb-21 is certified at
  exploitability 1.2e-5, yet its `color_swap_gap` is 0.58 (rb-12: 0.50; vanilla CFR 0.66 and 0.53):
  shipped rows differ from their images by up to 0.58 while the profile is essentially exact. This
  is Paper II's color-swap audit in small: CFR+ selects among equilibria, and the selection need not
  be symmetric. A gap is a symptom to investigate, a zero gap proves nothing, and only the
  exploitability grade is a certificate.

## Caveats (review-zoo)

- The `info_leak_key` exploitability depends on which leaked row the file keeps for each real
  infoset (the solver has no right answer; it solved a different game). Last-write-wins, the
  shipped choice, gives 0.2024 (Kuhn) and 0.6857 (Leduc); first-write-wins on the same run gives
  0.1667 and 2.5216. Quote it as "large under either choice", not as one number.
- For update bugs the self-BR meter equals the exact grade by construction (it is an exact BR in a
  correct model), so "the meter catches them" is a property of this meter, not an empirical finding.
  A solver that watched only its regret meter would pass `players_off_by_one` (regret meter 1e-4).
- `color_swap_imposed` merges rows only between an infoset and a different image; it does not tie
  the actions of an infoset that is its own image (for example seat 1's first reorder in
  rb-pennies, `BR` vs `RB`). A stricter imposition might cost more or less.
- Not done: enforcing a TRUE symmetry on top of a bug the symmetry gap would have caught (Paper
  II's exact sequence). None of the zoo's bugs breaks the color symmetry of a dealt game
  (`chance_ignored` keeps it, since uniform chance over a symmetric outcome set is symmetric), and
  the clean solver's own gap is already large (above), so the gap could not serve as the tripwire.
